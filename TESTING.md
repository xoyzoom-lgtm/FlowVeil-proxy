# Ручная проверка FlowVeil (для владельца)

Код и юнит-тесты проверяют логику, но не реальные сети, прошивки и Windows. Здесь то, что можно проверить только руками.
Для каждого сценария: шаги → ожидаемый результат → что скопировать в отчёт.

**Как получить отчёт:** Android и Windows: главный экран → «Почему не работает?» → «Скопировать отчёт». В отчёте нет ссылок, ключей, адресов и названий сетей: версия, система, тип сети, версии ядер, коды причин, последние строки журнала. Если что-то не так, пришлите его в Telegram @GxoyzoomG.

Отмечайте результат: ✅ работает / ❌ не работает (приложите отчёт) / ➖ не проверял.

## 6. Инструменты для провайдеров (P2)

1. Android: откройте из Telegram/браузера ссылку `flowveil://add?url=<закодированная подписка>&name=Мой%20сервис`. Ожидается: приложение открывается, подписка добавляется, в списке она называется «Мой сервис» (пока панель не прислала свой `profile-title`, он важнее).
2. То же на Windows (приложение закрыто и открыто): ссылка из браузера → откроется «Серверы» с новой подпиской, тост «Добавлено N серверов в «Мой сервис»». Повторная ссылка → «Такая подписка уже есть».
3. Панель отдаёт `support-url`: на карточке подписки есть кнопка «Поддержка». Если в заголовке `file:///…` или `javascript:…` — кнопки нет.
4. Сайт → «Для провайдеров»: заполнить адрес и название, «Создать», «Лист для печати» → в окне печати один лист с QR-кодом; отсканировать QR приложением FlowVeil (Android: «+» → QR).

## 7. Переключение при сбое сервера

Без сервера, который можно «уронить», проверить это нельзя — нужен тестовый сервер или подписка, где можно выключить один сервер.
1. Windows: подключиться к серверу A, затем отключить его на стороне сервера (или заблокировать его адрес в брандмауэре Windows). Ожидается: через ~30–60 секунд всплывающее уведомление «Сервер не отвечал — переключился» и выбран другой сервер; интернет снова работает. Записи в Логах: «Failover: …».
2. Windows: отключить сетевой кабель/Wi-Fi целиком. Ожидается: переключения нет (сервер не виноват).
3. Windows: «Переключаться при сбое сервера» выключить → при падении сервера ничего не происходит.
4. Android: то же для сервера в текущей подписке; затем уронить все серверы одной подписки при второй рабочей подписке → переход во вторую; выключить «Переключаться между подписками» → перехода нет.
5. Подписка с истёкшим сроком или без трафика не должна получать переключение.

## 8. Белые списки, конфликтующие программы, профили правил

1. Android, мобильная сеть с белыми списками: включить автообход, отключить Wi-Fi. Ожидается: приложение само находит рабочий «белый» сервер и интернет работает; «Почему не работает?» не ругается. Раньше после смены адреса пинга оно не находило сервер.
2. Windows: запустить zapret (winws.exe) и открыть FlowVeil. Ожидается через пару секунд окно «Обнаружено конфликтующее ПО: zapret (winws.exe)»; «Выгрузить процессы» закрывает процесс (если zapret запущен от администратора, а FlowVeil нет, появится честное «не удалось закрыть»). Повторно в этом же запуске окно не появляется, пока не появится новая программа; перед нажатием «Подключить» проверка идёт снова.
3. Windows и Android: «Профиль правил» → «РФ напрямую»: российский сайт открывается напрямую (проверить IP на 2ip.ru и зарубежном сервисе), зарубежный через сервер. «Всё напрямую»: IP везде свой. «Всё через сервер»: IP везде серверный.

## 9. Автопереключение на мобильной сети (быстрее и надёжнее)

Всё ниже: «не проверено на устройстве», пока владелец не подтвердит. Нужен Android и мобильная сеть, где ограничения воспроизводятся (или режим, где отвечают только российские сайты). Журнал: Настройки → режим разработчика → журнал; «Скопировать отчёт» даёт текст без адресов.

| № | Сценарий | Ожидается | Статус |
|---|---|---|---|
| 9.1 | Холодный старт на ограниченной мобильной сети, сервер раньше уже работал здесь | Строка «quick path» в журнале, связь за < 15 с, итог эпизода `quick=ok` | не проверено |
| 9.2 | То же, но «быстрого» сервера нет (чистая установка) | Обычный поиск волнами, связь за < 45 с, `quick=no` | не проверено |
| 9.3 | Смена Wi-Fi ↔ мобильная сеть несколько раз подряд (каждые 2–3 с) | Нет серии «плохих серверов» в журнале; строки «not held against the servers» | не проверено |
| 9.4 | Три оператора (разные SIM) | У каждого свои результаты, сервер из истории одного не пробуется как «быстрый» у другого | не проверено |
| 9.5 | Режим экономии батареи включён | Поиск доходит до конца, проверки не обрываются по времени (`timed-out` в итоге близко к 0) | не проверено |
| 9.6 | Убить процесс :daemon системой (например, `adb shell am kill`) во время поиска | После перезапуска служба работает, состояние не сломано, журнал продолжается | не проверено |
| 9.7 | Нажать другой сервер во время поиска | Поиск прекращается, FlowVeil не переключает обратно, `ABORTED` в итоге | не проверено |
| 9.8 | Ядро перезапускается в момент переключения (например, смена сети во время поиска) | Строка «waiting for it to finish», повтор один раз, кандидат не помечен плохим | не проверено |
| 9.9 | Экран выключен, затем включён во время паузы после неудачного поиска | «pause ... cancelled (screen on)», проверка сразу | не проверено |
| 9.10 | Вернуться на Wi-Fi | Возврат на прежний сервер, российский сервер как замена не выбирается | не проверено |
| 9.11 | Проверки противоречат друг другу (часть иностранных адресов отвечает) | В журнале `UNSURE`, сначала быстрый путь, потом обычное переключение | не проверено |
