# Как помочь проекту

Спасибо, что хотите помочь FlowVeil. Коротко о главном.

## Сообщить об ошибке или идее
Откройте [задачу](https://github.com/xoyzoom-lgtm/FlowVeil-proxy/issues/new/choose): есть шаблоны для ошибки, предложения и ссылки провайдера, которая не открывается. **Не публикуйте** ссылку на подписку, ключи и IP серверов. О найденной уязвимости пишите приватно (см. [SECURITY.md](SECURITY.md)).

## Предложить изменение
1. Сделайте форк и создайте ветку от `main` (`fix/…`, `feat/…`). В `main` напрямую пушит только автор: каждый пуш туда публикует новую версию.
2. Android: Kotlin, Jetpack Compose, пакет `com.v2ray.ang` (его не менять). Windows: C#/.NET, WPF, логика в `windows/v2rayN/ServiceLib`.
3. Чистая логика лежит отдельно от интерфейса и покрыта тестами: Android — `android/V2rayNG/app/src/test/java/com/v2ray/ang/net/`, Windows — `windows/v2rayN/ServiceLib.Tests/`. Если меняете разбор ссылок, правила или обновление, добавьте тест.
4. Запуск тестов Windows: `cd windows/v2rayN && dotnet test --project ServiceLib.Tests/ServiceLib.Tests.csproj -c Release -p:EnableWindowsTargeting=true`. Android собирается в CI (`.github/workflows/build.yml`); пушьте в ветку `bypass-…`, там собираются оба приложения без публикации.
5. Тексты интерфейса — только в ресурсах (`res/values/strings.xml` и `res/values-ru/strings.xml`), не в коде.
6. Видимые пользователю изменения запишите в `CHANGES.md` (по-русски, простыми словами).

## Чего не делаем
- Не добавляем аналитику, трекеры и запросы к серверам разработчика.
- Не меняем ключ подписи и имя пакета: иначе у существующих пользователей перестанут ставиться обновления.
- Не выдаём приложение за другое (название, значок, `User-Agent`) и не расшифровываем чужие закрытые ссылки.
- В текстах для пользователей не называем FlowVeil «VPN-сервисом»: у проекта нет серверов.
